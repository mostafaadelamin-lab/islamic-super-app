# رتّل · Rattil — mobile app (Android + iOS)

Flutter app for Milestone 1: Quran (surah reader, Madinah Mushaf pages, search,
bookmarks), prayer times + qibla, optional account sync. Arabic (default, RTL)
and English (LTR). Free forever: no ads, no subscriptions, no purchases.

- App id / bundle id: `org.rattil.app` · display name: رتّل (ar) / Rattil
- **Flutter 3.41.6** (stable, Dart 3.11.4) — pinned in `pubspec.yaml` (`environment.flutter`).
  CI should use exactly this version (e.g. `subosito/flutter-action` with `flutter-version: 3.41.6`,
  or the Docker image `instrumentisto/flutter:3` which currently ships 3.41.6).
- Android: compile/target SDK from Flutter 3.41.6 defaults (SDK 36, build-tools 36), AGP 8.11.1, Gradle 8.14.
- Runtime dependencies (all open source): `shared_preferences`, `http`, `timezone`, `crypto`,
  `intl`, `flutter_localizations`; Milestone 2 added `just_audio` (recitation streaming),
  `flutter_local_notifications` (adhan), `sensors_plus` (qibla compass) and `hijri` (Hijri date). Dev: `flutter_test`, `integration_test`, `flutter_lints`, `mocktail`.

## Regenerating copied/generated files

```sh
tool/sync_assets.sh            # copy content/, shared-schemas, fonts, design tokens (byte-for-byte)
tool/sync_assets.sh --check    # CI: fail if any bundled copy differs from its source
dart run tool/gen_arb.dart     # shared i18n JSON + tool/i18n/mobile.*.json -> lib/l10n/app_*.arb
dart run tool/gen_arb.dart --check
flutter gen-l10n               # ARB -> lib/l10n/app_localizations*.dart (also runs on pub get / build)
python3 tool/gen_python_reference.py   # (from repo root) exact outputs of the Python reference for tests
```

Shared UI strings live in `packages/shared-schemas/i18n/{ar,en}.json`; strings only the mobile app
needs are in `tool/i18n/mobile.{ar,en}.json` (keys must be identical in both languages; the generator
also checks placeholders). The Quran text is never modified: `quran-render.json` is applied only to the
string handed to the `Text` widget (`QuranText` in `lib/ui/widgets.dart`).

## Test, analyse, build

All commands run from `apps/mobile`. Without a local Flutter install, prefix with
`docker run --rm -v "$PWD/../..":/w -w /w/apps/mobile instrumentisto/flutter:3`.

```sh
flutter pub get
flutter analyze                                     # expected: No issues found!
dart format --output=none --set-exit-if-changed lib test test_contract integration_test tool   # page width 120 (analysis_options.yaml)
flutter test                                        # unit + widget + screenshot tests
flutter test --coverage                             # coverage/lcov.info
RATTIL_SCREENSHOT_DIR=build/screenshots flutter test test/screenshots
RATTIL_API_URL=http://127.0.0.1:8000 flutter test test_contract   # needs services/api running
flutter test integration_test/app_test.dart -d <emulator-or-simulator-id>
flutter build apk --debug          # build/app/outputs/flutter-apk/app-debug.apk
flutter build apk --release        # signed with the debug key in M1 (no release keystore)
flutter build ios --no-codesign    # macOS only
tool/collect_evidence.sh && python3 tool/summarize_evidence.py   # writes tests/evidence/mobile/
```

What the tests cover:

- **Prayer** (`test/unit/prayer_test.dart`): all 38 adhan-js vectors (`tests/vectors/prayer-times.json`,
  ≤ 2 min, UTC and local), exact-minute equality with the Python reference for 42 cases, qibla vectors
  (≤ 0.5°) and 1e-9° agreement with Python, DST transitions (London, New York, Sydney, Cairo), invalid input
  (latitude/longitude range, NaN, unknown method/asr, impossible dates, polar night), Dhuhr offset,
  `ishaMinutes`, Hanafi Asr, twilight-angle high-latitude rule, manual adjustments, Python-style rounding.
- **Quran integrity** (`test/unit/quran_integrity_test.dart`): bundled files byte-identical to
  `content/quran/dist`, 114 surahs / 6236 ayahs, counts = `tests/vectors/quran-reference.json`,
  `allAyahsSha256` and every `surahSha256` from `integrity.v1.json`, every ayah equal to the pinned
  upstream quran-json 3.1.2 file (whose SHA-256 is checked), 604 contiguous pages, page spot checks, juz.
- **Text**: normalisation vectors, render map never touches stored/searched/hashed text, search.
- **Bookmarks & sync** with a mocktail `http.Client` + in-memory fake of API.md: LWW conflicts both ways,
  tombstones, `since`, offline/timeout/status-code mapping, malformed payloads, account flows.
- **Widgets**: every screen and control (tap → asserted state), navigation, RTL (ar) / LTR (en),
  text scale 1.5 and 2.0, small phone, `androidTapTargetGuideline`, `iOSTapTargetGuideline`,
  `labeledTapTargetGuideline` on every screen in ar and en, light and dark; `textContrastGuideline` on every
  screen in English (see limitations) plus an analytic WCAG check of every theme colour pair.
- **Screenshots**: PNGs of the main screens rendered with the real fonts, ar and en, light and dark.

## Milestone 2

- Navigation: Home / Quran / Prayer / Adhkar / More (More: bookmarks, search, Hisn al-Muslim, tasbih,
  qibla, Hajj & Umrah, settings, about).
- Mushaf: 604 Madinah pages drawn line by line from `mushaf-lines.v1.json` (15 justified lines, one font
  size per page so every line fits), book-like RTL page turn, tap an ayah to play / bookmark / copy.
- Recitation: per-ayah MP3 streamed from everyayah.com (basmala before ayah 1 except surahs 1 and 9),
  repeat count and reciter saved in settings, automatic page turn while playing.
- Adhkar counts and sessions (`lib/domain/adhkar.dart`) are re-derived in tests from the Hisn chapter
  "أذكار الصباح والمساء"; adhkar and the Hajj guide show a "pending religious review" notice.
- Adhan notifications are scheduled for the next 7 days (at most 60 pending) through
  `flutter_local_notifications`; they need a real device to verify.
- Not done in M2: magnetic declination is not corrected (compass shows magnetic heading); no lock-screen /
  background audio service (iOS `UIBackgroundModes=audio` only); the Hajj guide is Arabic-only.

## Limitations / open items (Milestone 1)

- **APK not built in the M1 sandbox**: the Android Gradle Plugin is only published on Google Maven
  (`dl.google.com`), which the sandbox egress proxy refuses (`maven.google.com` 301-redirects there).
  `flutter build apk` fails at plugin resolution. See `tests/evidence/mobile/build_apk_*.log`. CI with normal
  internet access should build it unchanged.
- **iOS not built** (no macOS host). The `ios/` project is generated (bundle id `org.rattil.app`,
  `CFBundleLocalizations` ar/en, `NSAllowsLocalNetworking` for the dev API).
- **Integration test not run on an emulator/simulator** (no KVM, no macOS). It was analysed, and a temporary
  copy with mocked storage passed on the headless `flutter-tester` device
  (`tests/evidence/mobile/integration_test_headless.txt`). CI must run it on a real emulator/simulator.
- `textContrastGuideline` samples rendered pixels and is reliable only with Flutter's solid-glyph test font,
  which has no Arabic glyphs; contrast is therefore checked on English screens (same colours) and analytically
  for all theme colour pairs (`test/unit/theme_contrast_test.dart`).
- (Superseded in M2: the Mushaf now follows the printed 15-line layout.)
- The auth token is kept in `shared_preferences` (not the Keychain/Keystore) in M1. Only bookmarks are synced
  (settings sync endpoints exist in the API but are not used yet). Tombstones are never purged.
- No "use my location" (M1 and M2). The compass sensor and prayer notifications were added in M2.
- Plain HTTP is allowed only to `10.0.2.2`, `localhost` and `127.0.0.1` (Android network security config)
  for the development API; everything else requires HTTPS.
- The English translation's licence review is pending (see the About screen).
